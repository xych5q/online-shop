## 四、全量回归现状（如实记录，含遗留）

`develop` 上测试类共 11 个。本次把可编译的 8 个类整体跑了一遍（MySQL 测试库 `onlineshop_test`）：

| 测试类 | 条数 | 结果 |
| --- | --- | --- |
| BuyerApiTest | 8 | 通过 |
| CartApiTest（本次新增） | 20 | 通过 |
| FavoriteApiTest | 11 | 通过 |
| OrderServiceTest | 17 | 通过 |
| StockCouplingTest | 8 | 通过 |
| UploadsResourceTest | 3 | 通过 |
| SellerCustomerApiTest | 4 | 3 失败（401） |
| SellerHistoryApiTest | 6 | 5 失败（401） |
| **合计** | **77** | **69 通过 / 8 失败** |

**8 条失败的根因（已定位，不属本次改动、也不是业务缺陷）**：`OrderServiceTest` 的 `@BeforeEach` 调
`sellerRepository.deleteAll()` 后只回建一条用户名非 `admin` 的卖家，导致其后执行的
`SellerCustomerApiTest` / `SellerHistoryApiTest` 里硬编码的 `admin / seller123` 登录返回 401。
单独执行这两个类时 10/10 全部通过，可证明是**测试类之间的状态污染**，不是接口问题。
建议修复方式：`OrderServiceTest` 改为只清理自己造的数据，或在 `@AfterEach` 回建 `admin`；归 W3-5 / L3-7 处理。

**另有 3 个测试类仍编译不过**：`CatalogApiTest`、`SellerAdminApiTest`、`TradeFlowTest` 仍在引用
迭代 3 已删除的 `Product.Status.FROZEN` / `SOLD_OUT`、`frozenBy` / `frozenAt`、`ProductService.freeze`。
这是迭代 3 已知阻塞（登记在 W3-5 退役登记），本次未改动他人测试文件，只如实登记。
