# 基线需求验收材料清单（10-15）

验收顺序：**需求 → 代码 → 构建 → 部署 → 运行**。五项缺一不可，缺项 = 延后 = 拿不到第二期升级需求。

## 1. 需求

| 材料 | 位置 | 状态 |
| --- | --- | --- |
| 需求规格说明书（**增值后**，非口述照抄） | `docs/requirements/需求规格说明书.md` | ☐ |
| 用例表 | `docs/requirements/用例表.md` | ☐ |
| 业务流程图 | `docs/requirements/业务流程图.md` | ☐ |
| 需求问题库（洽谈证据） | `docs/requirements/需求问题库.md` | ☐ |

## 2. 代码

| 材料 | 位置 | 状态 |
| --- | --- | --- |
| 规范目录结构、包命名 | `src/main/java/` | ☐ |
| 从 Git 平台下载（**禁止用 U 盘**） | GitHub 仓库 + tag `v0.1-iter1` | ☐ |
| 提交记录可区分到个人 | GitHub Insights / `git log` | ☐ |

## 3. 构建

| 材料 | 位置 | 状态 |
| --- | --- | --- |
| 构建工具（Maven） | `pom.xml` | ☐ |
| 构建脚本 | `build/build.sh` | ☐ |
| **构建手册**（讲清源码 → 二进制全过程） | `build/构建手册.md` | ☐ |

> 实在无法自动化的环节可以手工，但必须能讲清楚每一步。

## 4. 部署

| 材料 | 位置 | 状态 |
| --- | --- | --- |
| Dockerfile | `deploy/Dockerfile` | ☐ |
| **Docker 镜像**（标准动作） | 镜像文件或仓库地址 | ☐ |
| 部署脚本 / 部署手册 | `deploy/部署手册.md` | ☐ |

## 5. 运行

| 材料 | 位置 | 状态 |
| --- | --- | --- |
| 测试用例清单 | `test-cases/测试用例清单.md` | ☐ |
| 自动化测试脚本（JUnit / Selenium / JMeter） | `src/test/java/`、`test-cases/` | ☐ |
| **屏幕录制演示视频**（无自动化时必交） | `test-cases/` 或 Release 附件 | ☐ |

## 验收前自检（组内预演一遍）

1. 新机器 clone 仓库 → 按构建手册从零构建 → 成功 ☐
2. 按部署手册部署 / 起镜像 → 能访问 ☐
3. 跑一遍测试用例 → 通过 ☐
4. 录一遍演示视频 → 可播放 ☐
5. 5 个人各自能讲清"我做了什么 + 怎么构建部署" ☐

> "我本地跑通了"不算数。验收标准是**别人按你的文档能复现**。
