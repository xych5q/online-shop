## 1. 引言

### 1.1 目的
定义"单卖家在线购物系统"基线版本的功能边界与业务规则，作为设计、开发、测试与验收的统一依据。

### 1.2 范围
**做**：单卖家商品发布与管理、买家免注册排队购买意向、口令码自助服务、交易冻结与结果标记、历史档案。
**不做**（需求方明确排除）：注册/登录（买家侧）、线上支付、物流、购物车、搜索分类、评价、库存、买家订单历史、App/小程序。

### 1.3 术语
| 术语 | 含义 |
| --- | --- |
| 口令码 | 买家提交意向后获得的唯一凭证，8 位大写字母数字，仅提交成功时显示一次 |
| 冻结 | 商品因进入交易或卖家手动操作而暂停接收新意向的状态 |
| 递补 | 交易失败后，队列下一位自动进入交易 |
| 重新排队 | 失败买家再次入队，排到队尾、提交时间刷新、口令码不变 |

### 1.4 需求矛盾识别与裁决（口径冲突记录）

原始需求为带噪声的口述口径，编写时识别出以下表面矛盾，均经澄清后裁决并回写正文：

| # | 表面矛盾 | 裁决结论 | 依据 |
| --- | --- | --- | --- |
| C1 | 需求方称"无注册"，同时要求"卖家可修改密码"——没有注册哪来密码？ | 买家完全无账号；**卖家账号由系统指定**（初始化生成用户名与随机初始密码，首次启动打印），故"无注册"与"改密码"不冲突 | [[需求问题库]] 澄清记录 |
| C2 | "先到先得排队"与"卖家处理交易"并存，易误解为卖家可挑选买家 | 卖家**不可挑人**，队首自动进入交易、系统自动冻结；卖家仅有"标记结果"与"冻结/解冻"两项手动操作 | [[需求问题库]] #8 答复 |
| C3 | "线下交易"与"系统内标记结果"的边界 | 系统只做意向排队与状态记录，**资金与货品交割完全在线下**，平台不参与担保（见第 6 节免责声明） | 老师口述需求 |
| C4 | "无通知功能"与"买家需要知道结果"的张力 | 系统明确**无任何通知机制**（无邮件/短信/站内信），买家凭口令码自助查询感知状态变化——这是有意取舍，非遗漏 | [[需求问题库]] #2 答复 |

## 2. 角色与权限

| 角色 | 说明 | 入口 |
| --- | --- | --- |
| 卖家 | 唯一，系统指定账号（无注册），登录后台管理商品与交易 | `/admin` |
| 买家 | 免注册，凭口令码自助操作 | `/` |
| 系统 | 自动执行：与队首进入交易、冻结、失败递补、口令码失效 | — |

## 3. 功能需求

### 3.1 卖家端（FR-S）
- **FR-S1 卖家登录**：用户名 + 密码；错误提示"用户名或密码错误"；无注册、无退出登录。
- **FR-S2 修改密码**：验证原密码；新密码 ≥ 8 位；成功后旧密码立即失效。
- **FR-S3 发布商品**：名称必填 ≤100 字、描述选填 ≤2000 字、价格必填 >0（人民币两位小数）、图片选填 JPG/PNG ≤5MB；**已有在售/交易中商品时禁止发布**；发布后即"在售"，不可修改。
- **FR-S4 手动冻结/解冻**：仅"在售"可手动冻结；**仅手动冻结的商品可手动解冻**；交易中的商品必须先标记交易结果。
- **FR-S5 意向购买人管理**：查看排队列表（姓名、电话、提交时间、位次）；**卖家不可挑人**，按先到先得与队首交易；后台全程不显示、不记录口令码。
- **FR-S6 标记交易结果**：仅"成功/失败"两档；成功后不可撤销；成功 → 商品下架进历史、队列剩余全部转失败、全部口令码失效；失败 → 队列有人自动递补、队列空自动恢复在售。
- **FR-S7 失败意向处置**：交易失败后，该单意向是"作废"还是"重新排队"由**卖家在后台逐单确认**（非系统自动入队）；重新排队排队尾、原口令码继续有效；重排次数**无上限**。
- **FR-S8 手动下架**：**不因有排队意向而禁止**（2026-10-07 拍板）；进入历史；队列剩余意向转失败、**口令码全部失效**（查不到、改不了、撤不了）；**系统无通知功能**，买家仅凭口令码自查发现。
- **FR-S9 历史商品**：只读档案，按成交时间倒序、每页 10 条；每条记录包含**商品自身字段**（名称、描述、图片、价格、发布时间、最终交易结果（成功成交 / 手动下架）、交易完成时间）与**意向流水**（姓名、电话、提交时间、终态三档：成功/撤销/失败）；**不记录口令码**；支持翻页检索。

### 3.2 买家端（FR-B）
- **FR-B1 浏览商品**：在售商品的名称/描述/图片/价格；无图显示占位图（已定）；描述为空则**留空**，不加"卖家没有填写描述"等默认文案（2026-10-07 拍板）；无商品显示"暂无商品在售"；交易中显示"商品交易中"。
- **FR-B2 提交意向**：姓名 + 电话必填（不校验格式；需求方**明确坚持完全不校验**，不做"11 位数字"等格式检查，填错责任在买家）；成功即入队并获口令码（**仅显示一次**，提供复制与"请截图保存"提示）；同一人重复提交不去重。
- **FR-B3 凭码查询**：位次、提交时间、是否已进入交易。
- **FR-B4 凭码修改**：改姓名/电话，不改变位次；修改后卖家后台与历史记录均只显示**最新**的姓名电话，不保留改动前的旧记录。
- **FR-B5 凭码撤销**：撤销后意向进入"已撤销"终态（历史留痕）、口令码失效；**交易中买家仍可撤销**（2026-10-07 拍板，口令码在交易结束前始终有效）——若队首撤销：交易终止、撤销者口令码失效；队列仍有排队意向则**下一位自动递补进入交易、商品保持冻结**，队列为空则**商品自动恢复在售**；撤销按钮**无需隐藏**。

## 4. 业务规则（状态机）

### 4.1 商品状态机
`在售 →（手动冻结）→ 已冻结[manual] →（解冻）→ 在售`
`在售 →（队首**自动**进入交易，同时自动冻结）→ 已冻结[auto] →（标记成功）→ 已下架`
`已冻结[auto] →（标记失败且队列空）→ 在售`
`在售 / 已冻结[manual] →（手动下架）→ 已下架`
- 同一时间最多一件商品处于在售/冻结
- **队首进入交易与冻结均由系统自动完成**，卖家后台无"进入交易"操作（2026-10-07 拍板；后台手动仅"标记交易结果"与"冻结/解冻"两项）
- 手动下架**不因有排队意向而禁止**；下架后排队意向口令码全部失效
- 冻结期间不接收新意向；无超时自动解冻
- 买家端对手动冻结与交易冻结**不区分**文案
- **「进入交易」的触发机制**（2026-10-13 增补，回应第 1 次评审技术意见 #1「自动要写清什么条件触发」）：
  - 触发者：**系统**（`TradeService.enterDeal`），取队列首位，**卖家不可挑人**；
  - 触发条件：商品处于**在售**状态，且该商品存在「排队中」的意向；
  - 触发动作：队首意向置「交易中」，商品置「已冻结」、`frozenBy='auto'`、`frozenAt=当前时间`——**冻结由系统自动完成，卖家无需另行操作**；
  - 自动递补：交易失败后若队列仍有排队意向，下一位**由系统自动递补**进入交易、商品保持冻结，卖家无需再次操作；
  - **待澄清（Q6，已提交 [[需求问题库]] #10）**：需求方第 8 条答复要求「买家提交意向后队首自动进入交易」。若照此实现（提交即冻结），因 FR-B1 / FR-B2 规定「商品交易中不接收新意向」，第二位及之后的买家将无法提交，排队队列无法形成。当前实现保留外部触发入口以维持排队与位次功能；该差异已提交需求方澄清，收到答复后立即对齐。**本组处置决定（2026-10-13，组长陈星宇）**：在需求方答复前维持现实现，保证排队、位次与递补功能可用；一旦答复明确，立即按答复对齐代码与文档。

### 4.2 意向状态机
`排队中 →（进入交易）→ 交易中 →（标记结果）→ 成功 / 失败`
`排队中 / 交易中 →（买家撤销）→ 已撤销`（交易中撤销：交易终止、后续队列递补；队列空则商品自动恢复在售）
终态三档：**成功 / 撤销 / 失败**；口令码随终态失效（重新排队除外，见 4.3）。

> **2026-10-13 代码对齐记录（FR-B5）**：原实现为「交易中拒绝撤销」（`IntentService.cancel` 抛「你已进入交易，无法自行撤销」），与 FR-B5 拍板口径矛盾。现已改为：交易中撤销 → `TradeService.abortDealByBuyer` 置该意向为已撤销并终止交易 → 队列有人则下一位自动递补（商品保持冻结）、队列无人则商品恢复在售；口令码随终态失效。补测试用例 17（交易中撤销且递补）、18（交易中撤销且队列空恢复在售），`mvn test` 18 组全通过。

### 4.3 排队与口令码规则
- 排队按提交时间先到先得；冻结发生在进入交易时
- 口令码全局唯一、仅显示一次、不可找回
- 失效条件：交易结束（成功/失败）、意向撤销、商品下架
- 重新排队不换码；重排以新提交时间计位次

## 6. 非功能需求
- 终端：仅 Web（桌面浏览器）
- 密码存储：BCrypt 加盐哈希；卖家密码长度 ≥ 8 位（FR-S2）
- 数据持久化：关系数据库（H2/MySQL），**核心数据（商品/意向/账户）重启不丢失**
- **关键操作审计**：冻结/解冻、修改密码、标记交易结果、手动下架等后台关键操作均记录操作时间戳，可在后台追溯
- **卖家后台易用性**：后台入口唯一（`/admin`）、布局清晰；操作流程简洁（核心动作不超过两步）；历史商品支持按成交时间倒序浏览与翻页检索
- **空态提示**：无在售商品显示"暂无商品在售"；交易中显示"商品交易中"；无效口令码给出明确错误提示
- 图片：服务端本地存储，URL 访问
- **线下交易免责声明**：本系统仅提供意向排队与状态管理；交易的资金结算与货品交割由买卖双方**线下自行完成**，平台不担保交易真实性、不参与纠纷仲裁，买家应审慎核实后再线下交易
