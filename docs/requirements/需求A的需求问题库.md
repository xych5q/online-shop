## 附二：A.2 需求方确认的 7 项需求空白及衍生风险（留痕）

需求方对 A.2 七项追问的答复**全部为「需求里没有 / 没定义」**，即实质接受空白。本组判定：**「需求没写」≠「已决策不做」**，必须在 SRS 中固化为「本版本明确不做项」并附风险告知。

> 其中第 7 项（旧系统数据切换）已于 10-20 19:24 由需求方指定 **B 方案**闭环；其余 6 项维持空白。

| 空白项 | 需求方口径 | 对应条目 |
| --- | --- | --- |
| 买家排队位次查询 | 无「我的意向 / 我的排队」页，无替代入口 | A.2.2-6 |
| 买家取消意向 | 无「取消意向」按钮，只能等卖家标记失败 | A.2.2-9 |
| 重置买家密码 | 无此能力；找回 / 自改 / 注销三个口子都没有 | A.2.1-9 |
| 联系电话填错修正 | 买家不能改、卖家不能代改，无口子 | A.2.1-8 |

**衍生风险（单项可接受，叠加后产生客户未预见的系统性风险）**：

- **R-A 队首阻塞链（最高优先级，由「无位次查询 + 无取消 + 电话不可改」叠加）**：买家提交意向 → 看不到位次不知何时轮到 → 轮到队首时卖家按电话联系不上 → 买家不能主动退出 → 卖家只能走「进入交易 → 标记失败」强行清退 → 清退期间商品被冻结、阻塞后续所有人。无效意向清理成本极高。
  - **10-20 19:24 升级**：需求方既**不采纳**「卖家排队阶段清退意向」（A.2.4-4），又**否定**了「跳过队首挑人」（A.2.3-9），因此清退只能**逐个**走「进交易 → 标失败」的完整交易生命周期——一条联系不上的意向就要占用一整个交易流程，阻塞链长度与队列长度等长。**这是本版本最需要向客户书面告知并留痕确认的风险。**
- **R-B 队列永久污染（由「无取消 + 无去重」叠加）**：灌入容易、清理极难，恶意或误操作提交的意向会永久占用队列，只能靠卖家逐条标记失败；叠加多商品 + 库存机制后影响面放大。
- **R-C 账号不可恢复且不可清理**：忘密码 / 电话填错 → 账号不可用；无注销 → 永久滞留；商家仍可见其完整手机号且不脱敏，合规风险叠加。
- **R-D 买家「黑盒」体验**：下单后看不到位次、看不到进展、收不到任何通知，只能被动等待线下联系。
- **R-E 无真实身份的线下交易风险**：售后与纠纷场景下卖家仅掌握用户名 + 电话，缺失真实姓名。
