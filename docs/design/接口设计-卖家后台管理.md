# 卖家后台管理模块 · RESTful API 接口设计文档

> 模块：卖家后台（类别管理 / 商品管理）　|　版本：v1.0 · 2026-11-03　|　适用范围：挑战需求 A.1.2（类别管理）、A.1.2-4（改挂类别）、A.1.3-5（手动调库存）、商品上下架

## 一、通用约定

**1. 接口前缀**：所有接口以 `/api/seller/` 开头（卖家后台模块）。

**2. 鉴权**：除登录外，所有接口需在请求头携带卖家 token：

```
X-Token: <登录返回的 token>
或
Authorization: Bearer <token>
```

校验失败返回 `401 {"error": "未登录或登录已失效"}`。

**3. 统一返回格式**：

| 场景 | HTTP 状态码 | 响应体 |
|---|---|---|
| 成功 | 200 | `{ "ok": true, ...业务数据 }` |
| 参数校验失败 | 400 | `{ "error": "第一条校验错误文案" }` |
| 业务规则拦截 | 400 | `{ "error": "中文提示文案" }` |
| 资源不存在 | 404 | `{ "error": "中文提示文案" }` |
| 未预期异常 | 500 | `{ "error": "服务器内部错误" }` |

**4. 商品状态枚举**（上下架接口涉及）：

| 状态值 | 含义 | 说明 |
|---|---|---|
| `on_sale` | 在售 | 买家可见 |
| `frozen` | 已冻结 | 手动冻结或交易中 |
| `off_shelf` | 已下架 | 手动下架或交易成功售出 |
| `sold_out` | 售罄 | 库存归零自动触发，补库存可回在售 |

## 二、接口明细

### 1. 新增类别

| 项 | 内容 |
|---|---|
| **URL** | `POST /api/seller/categories` |
| **Method** | POST |
| **鉴权** | 是（X-Token） |

**请求体（JSON）：**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 类别名称，去空格后 1~50 字 |
| `parentId` | long | 否 | 父类别 id。**不传 = 一级类别**；传 = 在该一级类别下建二级类别 |

**校验规则：**
- `name` 必填，≤50 字
- `parentId` 传入时必须存在，且必须是一级类别
- 同一父级下不允许重名

**成功返回（200）：**

```json
{
  "ok": true,
  "id": 3,
  "name": "手机配件",
  "parentId": 1,
  "createdAt": "2026-11-03T10:30:00"
}
```

**失败示例：**

```json
// 400 同级重名
{ "error": "同级类别名称已存在" }
// 404 父类别不存在
{ "error": "父类别不存在" }
```

### 2. 修改类别

| 项 | 内容 |
|---|---|
| **URL** | `PUT /api/seller/categories/{id}` |
| **Method** | PUT |
| **鉴权** | 是（X-Token） |

**路径参数：**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | long | 类别 id |

**请求体（JSON）：**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 是 | 新名称，去空格后 1~50 字 |

**校验规则：**
- 类别必须存在，否则 404「类别不存在」
- `name` 必填，≤50 字
- 改名后与同级其他类别重名 → 400「同级类别名称已存在」
- 仅支持改名；不支持改挂父级（需求未要求）

**成功返回（200）：**

```json
{ "ok": true }
```

**失败示例：**

```json
// 404
{ "error": "类别不存在" }
```

### 3. 删除类别

| 项 | 内容 |
|---|---|
| **URL** | `DELETE /api/seller/categories/{id}` |
| **Method** | DELETE |
| **鉴权** | 是（X-Token） |

**路径参数：**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | long | 类别 id |

**校验规则（核心：有商品不可删）：**
- 类别必须存在，否则 404「类别不存在」
- **一级类别下还有子类别** → 400「请先删除该类别下的子类别」
- **该类别下有商品**（一级类别则检查其下所有二级类别的商品）→ 400「该类别下还有商品，不能删除」
- 按 A.1.2-4，卖家应先把这些商品改挂到其他类别，再删除

**成功返回（200）：**

```json
{ "ok": true }
```

**失败示例：**

```json
// 400 有商品不可删
{ "error": "该类别下还有商品，不能删除" }
// 400 有子类别
{ "error": "请先删除该类别下的子类别" }
```

### 4. 商品修改类别（改挂）

| 项 | 内容 |
|---|---|
| **URL** | `PUT /api/seller/products/{id}/category` |
| **Method** | PUT |
| **鉴权** | 是（X-Token） |

**路径参数：**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | long | 商品 id |

**请求体（JSON）：**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `categoryId` | long | 是 | 目标**二级类别** id |

**校验规则：**
- 商品必须存在，否则 404「商品不存在」
- 已下架商品不可改挂（历史商品只读）→ 400「商品已下架」
- `categoryId` 必填；类别必须存在且为**二级类别**（一级类别不能挂商品）→ 400「类别不存在」/「商品必须挂到二级类别」

**成功返回（200）：**

```json
{ "ok": true }
```

**失败示例：**

```json
// 400
{ "error": "商品必须挂到二级类别" }
```

### 5. 手动调库存

| 项 | 内容 |
|---|---|
| **URL** | `PUT /api/seller/products/{id}/stock` |
| **Method** | PUT |
| **鉴权** | 是（X-Token） |

**路径参数：**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | long | 商品 id |

**请求体（JSON）：**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `stock` | int | 是 | 目标库存，**≥0**（0 表示清零） |
| `reason` | string | 否 | 调整原因，≤200 字（补货/盘点/损耗） |

**校验规则：**
- 商品必须存在，否则 404「商品不存在」
- 已下架商品不可调库存 → 400「商品已下架」
- `stock` 必填，≥0，否则 400「库存不能为负数」
- 每次调整写一条 `stock_log` 流水（操作人、调整前/后库存、变动量、原因、时间）

**状态联动：**
- 调整后库存 = 0 → 商品状态转 `sold_out`（售罄自动下架）
- 商品原为 `sold_out` 且调整后 ≥1 → 状态回 `on_sale`（A.1.3-5 补货恢复在售）

**成功返回（200）：**

```json
{
  "ok": true,
  "id": 5,
  "stock": 20,
  "status": "on_sale",
  "updatedAt": "2026-11-03T11:00:00"
}
```

**失败示例：**

```json
// 400
{ "error": "库存不能为负数" }
```

### 6. 商品上下架

#### 6.1 上架

| 项 | 内容 |
|---|---|
| **URL** | `POST /api/seller/products/{id}/onshelf` |
| **Method** | POST |
| **鉴权** | 是（X-Token） |

**路径参数：**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | long | 商品 id |

**请求体**：无

**校验规则：**
- 商品必须存在，否则 404「商品不存在」
- 仅 `off_shelf`（手动下架）状态可上架 → 否则 400「仅「已下架」商品可上架」
- `sold_out` 状态需先补库存（调库存 ≥1 后自动回在售）；交易成功售出的商品不可上架
- 上架后状态 = `on_sale`

**成功返回（200）：**

```json
{ "ok": true }
```

#### 6.2 下架

| 项 | 内容 |
|---|---|
| **URL** | `POST /api/seller/products/{id}/offshelf` |
| **Method** | POST |
| **鉴权** | 是（X-Token） |

**路径参数：**

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | long | 商品 id |

**请求体**：无

**校验规则：**
- 商品必须存在，否则 404「商品不存在」
- 交易冻结中（`frozen` 且来源为交易）须先标记交易结果 → 400「交易中的商品请先标记交易结果」
- 下架后状态 = `off_shelf`，记 `offShelfReason = "MANUAL"`、`closedAt = 当前时间`

**成功返回（200）：**

```json
{ "ok": true }
```

**失败示例：**

```json
// 400
{ "error": "交易中的商品请先标记交易结果" }
```

## 三、状态机速览（上下架 + 库存联动）

```
OFF_SHELF(手动) ──上架──▶ ON_SALE ──手动下架──▶ OFF_SHELF
                                  │
                             库存调为 0
                                  ▼
                             SOLD_OUT ──调库存 ≥1──▶ ON_SALE
```

## 四、错误码汇总

| HTTP | error 文案（节选） | 出现场景 |
|---|---|---|
| 401 | 未登录或登录已失效 | 未带/无效 token |
| 400 | 同级类别名称已存在 | 类别增/改重名 |
| 400 | 该类别下还有商品，不能删除 | 删有商品的类别 |
| 400 | 请先删除该类别下的子类别 | 删有子类别的一级类别 |
| 400 | 商品必须挂到二级类别 | 发布/改挂时挂一级 |
| 400 | 库存不能为负数 | 调库存传负值 |
| 400 | 仅「已下架」商品可上架 | 上架非下架商品 |
| 404 | 类别不存在 / 商品不存在 | 资源不存在 |

## 五、迭代二评审整改补充（2026-11-04）

### 5.1 商品列表接口（卖家后台管理主入口，整改一）

| 项 | 内容 |
|---|---|
| **URL** | `GET /api/seller/products?status=all&page=1&size=10` |
| **Method** | GET |
| **鉴权** | 是（X-Token） |

**查询参数：**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `status` | string | 否 | `all`（默认）/ `on_sale` / `frozen` / `off_shelf` / `sold_out`；非法值 400「参数错误」 |
| `page` | int | 否 | 从 1 起，默认 1；越界取最后一页 |
| `size` | int | 否 | 每页条数，默认 10，上限 100 |

**成功返回（200）：**

```json
{
  "ok": true,
  "page": 1, "pageSize": 10, "totalPages": 1, "total": 2,
  "items": [
    {
      "id": 5, "name": "机械键盘", "status": "on_sale",
      "stock": 20, "price": 199.00,
      "categoryId": 7, "description": "九成新，青轴",
      "frozenBy": null, "imageUrl": "/uploads/kb.png",
      "pendingCount": 3, "inTransaction": false,
      "createdAt": "2026-11-04T10:00:00"
    }
  ]
}
```

- 排序：按 `createdAt` 倒序（最新在前）
- `pageSize`：实际生效的每页条数，入参超过上限 100 时按 100 截断后回显
- `frozenBy`：仅在冻结态有值（auto 交易中 / manual 手动停售），其余为 null
- `imageUrl`：主图取 sortOrder 最小的一张，无图回退旧单图字段，都没有返回 null
- `pendingCount`：该商品排队中（QUEUED）意向数；`inTransaction`：是否存在进行中交易

### 5.2 管理口径（整改二 / 三 / 四）

1. **售罄商品的管理入口 = 商品列表**：用 `status=sold_out` 筛出来操作（补货入口），**不再塞进历史**；
   `GET /api/seller/history` 与 `/history/{id}` 保持「只收手动下架（OFF_SHELF）」语义不变，不搞两套入口。
2. **overview 定位**：保留为「当前交易焦点」（在售/冻结/售罄单件 + 队列 + 当前交易 + 待处置失败意向）；
   商品管理以 5.1 列表为准。`canPublish` 在多商品发布（A.1.1-1）下**恒为 true**，字段保留兼容前端。
3. **库存流水口径**：任何从接口创建的商品，`ΣchangeAmount` 恒等于当前库存——
   发布时写一条 `{before:0, after:初始库存, change:初始库存, reason:"发布入库"}` 初始流水；
   成交扣减写 `reason:"成交扣减"`（系统自动）；手动调库存写卖家操作流水。
4. **富文本清洗**：发布入库前剥掉 `<script>` 标签及其内容（大小写不敏感），详情接口返回的富文本不携带脚本。
