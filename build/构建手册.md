# 构建手册

> 第 1 组 · 在线购物系统　|　版本：迭代 2（tag `v0.2-iter2`）　|　最后更新：2026-11-05
> 目标：让读者在一台**全新的机器**上，按本手册从源码构建出可运行的产物。

## 1. 环境依赖

| --- | --- | --- | --- |

## 3. 构建步骤（源码 → 二进制）

工程是 Maven 单模块，位于 `server/` 子目录，**pom.xml 不在仓库根目录**，所有 mvn 命令都要在该目录下执行。

```bash
cd server

mvn clean            # 1) 清理
mvn compile          # 2) 编译
mvn test             # 3) 跑单元测试，77 条
mvn package          # 4) 打包，产出 target/online-shop.jar
```

一键（脚本内部已切到 `server/`，在仓库根目录执行即可）：

```bash
bash build/build.sh
```

产物：`server/target/online-shop.jar`（约 49 MB，含全部依赖的 Spring Boot fat jar）。
文件名固定为 `online-shop.jar`，不随版本号变化，由 `pom.xml` 的 `<finalName>online-shop</finalName>` 决定。

## 4. 每一步发生了什么（讲清楚，验收会问）

1. `clean` 删除 `target/`，保证没有历史残留。
2. `compile` 把 `src/main/java` 编译为 `target/classes` 下的 `.class`。
3. `test` 执行 `src/test/java` 的 JUnit 用例，失败则构建中断；迭代 2 共 7 个测试类 77 条。
4. `package` 把 class + 资源 + 依赖打成可执行 jar，`application.yml` 与前端静态页一起打进去。
5. 依赖由 `pom.xml` 声明，Maven 从本地仓库/中央仓库解析，**不需要手动拷 jar**。

## 5. 构建结果校验

```bash
cd server
java -jar target/online-shop.jar --server.port=8090
curl -s http://localhost:8090/api/products | head -c 200
```

返回商品 JSON 即构建成功。完整验收用统一入口：

```bash
bash test-cases/verify-all.sh    # 单测 77 条 + 干净库起服务 + 接口冒烟 60 项 + 后台演示 18 项
```

## 6. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `no POM in this directory` | 在仓库根目录直接跑 `mvn` | pom 在 `server/` 下，先 `cd server`，或直接用 `build/build.sh` |
| 依赖下载超时 | 默认中央仓库慢 | 配置阿里云镜像 `$HOME/.m2/settings.xml`（Windows 下为 `C://Users//<用户名>//.m2//settings.xml`） |
| 测试用例失败 | 代码或环境问题 | 看 `server/target/surefire-reports/` |
| 编译报 Java 版本不符 | 用了 JDK 17 | 本项目要求 JDK 21（`pom.xml` 的 `java.version=21`），换 21 后重试 |
| 端口被占用 | 8080 或 8090 上已有实例 | 加 `--server.port=8091` 换端口 |
