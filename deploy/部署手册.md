## 1. 方式〇：云端构建镜像（本机没有 Docker 时用这条）

`.github/workflows/docker-image.yml` 在 GitHub Actions 上完成「单测 → 构建镜像 → 推送 GHCR → 起容器跑冒烟 → 导出 tar 挂 Release」，本机**一个 Docker 都不用装**。

```bash
# 方式 A：打 tag 即触发
git tag -a v0.1-iter1 -m "迭代 1 基线" && git push origin v0.1-iter1

# 方式 B：在仓库 Actions 页面选 “Docker Image” → Run workflow（tag 填 0.1-iter1）
```

产出物：

| 产物 | 位置 | 用途 |
| --- | --- | --- |
| 镜像 | `ghcr.io/xych5q/online-shop:0.1-iter1` | 验收材料里的"镜像地址"，对方 `docker pull` 即可 |
| 镜像 tar | Release 附件 `v0.1-iter1` | 需要交"镜像文件"时直接下载 |
| 冒烟结论 | Actions 运行日志 | 证明镜像能起来且 44 项断言全过，可截图 |

```bash
# 验收方拉取运行
docker pull ghcr.io/xych5q/online-shop:0.1-iter1
docker run -d --name online-shop -p 8080:8080 ghcr.io/xych5q/online-shop:0.1-iter1
curl -o /dev/null -w '%{http_code}\n' http://localhost:8080/api/product   # 期望 200
```

> GHCR 包默认是私有的。要到仓库 Settings → Packages（或该 package 的 Package settings）里改成 **Public**，否则对方拉不下来。

## 2. 方式一：Docker 镜像（推荐，课程标准动作）

### 1.1 一键（推荐）

在**仓库根目录**执行：

```bash
bash deploy/docker-verify.sh
```

脚本依次完成：宿主机跑 JUnit 单测（18 组，不通过就拒绝构建）→ 构建镜像 → 起容器 → 等待就绪 → 对容器实例跑 `test-cases/api-smoke.sh`（44 项断言）→ 导出镜像 tar 到 `dist/`。全过程结果写屏，可直接截图作为部署证据。

### 1.2 手动分步

```bash
# ① 构建镜像（注意：上下文是仓库根目录，因为 Dockerfile 要 COPY server/*）
docker build -f deploy/Dockerfile -t online-shop:0.1 .

# ② 起容器
docker run -d --name online-shop -p 8080:8080 -e TZ=Asia/Shanghai online-shop:0.1

# ③ 等就绪（/api/product 返回 200 即就绪；本服务没有 /health 端点）
curl -o /dev/null -w '%{http_code}\n' http://localhost:8080/api/product

# ④ 对容器实例跑冒烟
cd test-cases && BASE=http://localhost:8080 bash api-smoke.sh

# ⑤ 导出镜像作为验收材料
docker save online-shop:0.1 -o dist/online-shop-0.1-iter1.tar
```

### 1.3 docker compose（带数据卷，重启不丢数据）

```bash
docker compose -f deploy/docker-compose.yml up -d
docker compose -f deploy/docker-compose.yml logs -f
docker compose -f deploy/docker-compose.yml down        # 停容器
docker compose -f deploy/docker-compose.yml down -v     # 连数据卷一起删（重置数据）
```

### 1.4 构建上下文裁剪

仓库根目录已放 `.dockerignore`，把 `.git/`、`server/target/`、`server/data/`（本地 H2 数据）、`docs/`、`deploy/`、`test-cases/` 排除在构建上下文之外。不加它会显著拖慢构建，还可能把本地测试数据打进镜像层。

## 3. 方式二：直接运行 jar（不用 Docker）

```bash
# 打包（跑测试）
cd server && mvn -B clean package

# 运行（默认 8080；本仓库没有 prod profile，不要加 --spring.profiles.active）
cd server && java -jar target/online-shop.jar

# 换端口 / 换数据目录（多实例互不干扰时用）
java -jar target/online-shop.jar \
     --server.port=8090 \
     --spring.datasource.url="jdbc:h2:file:./data-smoke/onlineshop;DB_CLOSE_ON_EXIT=FALSE" \
     --app.upload.dir=./data-smoke/uploads
```

## 4. 配置项（与 `server/src/main/resources/application.yml` 一致）

| 配置项 | 键 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 端口 | `server.port` | `8080` | 容器内也是 8080，用 `-p` 映射到宿主机 |
| 数据库 | `spring.datasource.url` | `jdbc:h2:file:./data/onlineshop;DB_CLOSE_ON_EXIT=FALSE` | **H2 文件库**（不是 MySQL）；容器内路径为 `/app/data/onlineshop` |
| 数据库账号 | `spring.datasource.username` | `sa` | 密码为空 |
| H2 控制台 | `/h2-console` | 已开启 | 排障用，生产应关闭 |
| 上传目录 | `app.upload.dir` | `./data/uploads` | 商品图片落盘位置，容器内 `/app/data/uploads` |
| 卖家账号 | `app.seller.username` / `password` | `admin` / `seller123` | 首次启动由 `DataInitializer` 自动创建，**无注册入口** |
| 历史分页 | `app.history.page-size` | `10` | 卖家后台历史商品每页条数 |
| 时区 | `TZ` | `Asia/Shanghai` | Dockerfile 已设，避免时间戳差 8 小时 |

> 敏感值（初始密码等）不入库，通过环境变量或构建时 `--build-arg` 注入；当前为课程演示账号，明确的默认值写死在配置里以便一键复现。

## 7. 数据持久化与重置

- H2 文件库与上传目录都在容器的 `/app/data` 下（宿主机直跑时为运行目录的 `data/`）。
- **要持久化**：用 `docker-compose.yml`（已挂 `shop-data` 命名卷），容器 `stop`/`start` 后数据仍在。
- **要重置**：`docker compose down -v`；宿主机直跑则删掉 `server/data/` 后重启。
- 首次启动会自动建库表并写入卖家账号，无需手工初始化脚本。

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `docker build` 卡在下载依赖 | 访问 Maven 中央仓慢 | 换镜像源或挂代理；首次构建正常也要几分钟 |
| 容器起不来，日志报端口占用 | 宿主机 8080 被占 | 换映射端口 `-p 8090:8080` |
| 接口时间比本地时间差 8 小时 | 容器时区 | 已通过 `TZ=Asia/Shanghai` 修正 |
| `UnsupportedClassVersionError` | 早期基础镜像是 JDK 17，而 pom 用 Java 21 | 本版 Dockerfile 已统一为 21 / 21-jre |
| 后台登录后立刻 401 | token 失效或被新登录顶掉 | 重新登录；同一账号同时只允许一个有效 token |
| 无法发布商品 | 已存在在售/冻结商品（单品约束） | 先标记交易结果或手动下架 |
